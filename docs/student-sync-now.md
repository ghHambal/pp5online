# อัปเดตรายชื่อนักเรียนทันทีจากหน้าตั้งค่า ปพ.5

## สถานะ 20 ตุลาคม 2569

Frontend 10.22.991 แก้การเรียก GAS จากเบราว์เซอร์ผ่าน Edge Function `student-sync` โดยตรวจ JWT และสิทธิ์แอดมินจาก profiles ก่อนทุกครั้ง ใช้ Central GAS URL จากฐานข้อมูลล่าสุด ไม่ส่ง token ของผู้ใช้หรือ service_role key ไปยัง Google

เผยแพร่ GAS เป็นเวอร์ชัน 26 ผ่าน deployment เดิมแล้ว ตรวจ capability ได้ `studentSyncVersion: 2` รอบรายสัปดาห์ยังทำงานผ่าน GAS เดิม ไม่ต้องเปลี่ยน trigger

พบจาก Chrome ของผู้ใช้จริงว่า JSONP ถูก CORB บล็อก ส่วน server-side capability ผ่าน จึงเปลี่ยนเฉพาะงานซิงก์นักเรียนให้เรียกผ่าน Edge Function ไม่ได้ปิดระบบป้องกันของ Chrome

การตรวจ preview แบบอ่านอย่างเดียวด้วย Sheet ID ลงท้าย MK7Tw4 / studentsData ตอบว่าไม่พบแท็บ ต้องยืนยันแหล่งรายชื่อภาคเรียน 2 ก่อนเปลี่ยนค่าและนำเข้าจริง ไม่เลือกไฟล์อื่นแทนโดยเดา

ฐานข้อมูลจริง: ปีการศึกษา 2569 ภาคเรียน 2 และ RPC auto_enroll_students_by_room จำกัดเฉพาะปี/เทอมปัจจุบัน พร้อมรักษารายการยกเว้นของครู ไม่ต้องแก้ schema/RPC งานนี้ยังไม่ได้สั่งซิงก์รายชื่อนักเรียนจริง

## ขั้นตอนติดตั้ง Apps Script สำหรับโครงการอื่น / การติดตั้งซ้ำ

1. เปิดโครงการ Apps Script ตัวเดียวกับ Central GAS URL ในหน้าตั้งค่า → Sync Engine
2. สำรองโค้ดเดิม แล้วแทนโค้ด Central GAS ด้วยไฟล์ `gas/pp5-sync.gs` ในชุดงานนี้ ห้ามเพิ่มฟังก์ชันชื่อซ้ำกับไฟล์เดิม
3. คง Script Properties ของโครงการเดิมไว้ รวม SUPABASE_URL และ SUPABASE_SERVICE_ROLE_KEY ไม่คัดลอกคีย์ลงหน้าเว็บ
4. เลือก Deploy → Manage deployments → เลือก Web App ที่ใช้อยู่ → Edit → Version: New version → Deploy ใช้ URL /exec เดิมและสิทธิ์เดิม
5. เปิด URL เดิม เติม `?action=student_sync_capabilities&callback=pp5Probe` ต้องได้ `pp5Probe({"ok":true,"studentSyncVersion":2});` ขั้นตอนนี้ไม่เขียนข้อมูล
6. เผยแพร่ frontend จากไฟล์ที่เปลี่ยนในชุดงานนี้ หลัง GAS รุ่นใหม่พร้อมแล้ว

โครงการที่ตรวจแล้วคือ PP5_12569AM และใช้ deployment เดิม ห้ามเปลี่ยน URL หรือขยายสิทธิ์โดยไม่จำเป็น

## ใช้งาน

1. เปิดหน้าตั้งค่า → แหล่งข้อมูลนักเรียน ระบุ Google Sheet ID/URL, ชื่อแท็บ, แถวหัวตาราง
2. กด “ซิงก์นักเรียนตอนนี้” ระบบตรวจการเชื่อมต่อและอ่านค่าล่าสุด ไม่ใช้ Central GAS URL ที่ค้างในแคช
3. ตรวจภาคเรียน แหล่งข้อมูล จำนวนคนใหม่ คนเดิมที่เปลี่ยน คนกลับมาเรียน รหัสซ้ำ และคนที่ไม่พบในชีต รายละเอียดแสดงตัวอย่างกลุ่มละ 30 คน พร้อมห้องเดิม → ห้องใหม่
4. ถ้าพบรหัสซ้ำ ให้แก้ต้นทางก่อน ระบบจะไม่ให้ยืนยัน
5. กดยืนยันเพื่อบันทึกค่าตั้งแหล่งข้อมูลและอัปเดตนักเรียนทันที หากยกเลิกจะไม่บันทึกค่าตั้งใหม่และไม่เขียนรายชื่อนักเรียน
6. ตรวจผลและประวัติการซิงก์ล่าสุด หากตอบกลับช้าหรือขาดการเชื่อมต่อ งานบน GAS อาจยังทำต่อ ให้ตรวจประวัติ/Apps Script Executions ก่อนลองใหม่

## พฤติกรรมร่วมกับรอบอัตโนมัติ

- ใช้ฟังก์ชันแกนเดียวกัน และใช้ system_config ล่าสุดก่อน Script Properties ซึ่งเป็น fallback
- จับคู่ด้วย student_code เดิม ไม่ลบนักเรียนหรือคะแนน/ประวัติ
- ไม่ล้างค่าของนักเรียนเดิมเมื่อช่องในชีตว่าง และไม่ปิดสถานะคนที่หายจากชีต
- คงพฤติกรรมเปิดสถานะคนที่มีชื่อในชีตกลับเป็น active โดยหน้าตรวจสอบแจ้งจำนวนคนที่กลับมาเรียน
- มี Script Lock ป้องกันงานในโครงการ GAS เดียวกันซ้อนกัน รอบรายสัปดาห์บันทึก triggered_by=auto
- การยืนยันตรวจ fingerprint อีกครั้ง ถ้าแหล่งข้อมูลหรือภาคเรียนเปลี่ยนให้เปิดตรวจสอบใหม่
- การบันทึกเป็น batch ไม่ใช่ transaction ทั้งชุด หากล้มกลางทางอาจมีบางส่วนบันทึกแล้ว สามารถตรวจสอบและซิงก์ซ้ำด้วยรหัสเดิมได้
- ถ้าบันทึกนักเรียนแล้วแต่บันทึก log หรือผูกห้องไม่สำเร็จ ระบบรายงานคำเตือนแยกจากผลบันทึกนักเรียน

## ตรวจสอบในเครื่อง

- `node tests/student-sync-preview.mjs`: preview ไม่เขียนข้อมูล, counts, รหัสซ้ำ, fingerprint เปลี่ยน, ค่าว่าง, pagination เกิน 1,000 คน, ลำดับ config, release lock เมื่อเกิดข้อผิดพลาด
- `node --check js/sync.js` / `js/views.js` / `js/student-sync-preview.js` และ `node --check < gas/pp5-sync.gs`
- `npm run build`
- ทดสอบหน้าต่างใน Chrome ด้วยข้อมูลจำลอง: รายละเอียดห้องเดิม/ใหม่ ยกเลิก และยืนยัน ไม่เรียกนำเข้าข้อมูลจริง

## ตรวจสอบตัวกลางเซิร์ฟเวอร์

- `node tests/student-sync-proxy.mjs`: ตรวจไม่มี token / สิทธิ์ครูต้องถูกปฏิเสธก่อนเรียก GAS, จำกัด URL และ redirect เฉพาะ Google, parse JSONP เป็น JSON โดยไม่ eval, ต้องมี fingerprint ก่อน sync, แยก error ขั้น preview กับขั้นเขียนข้อมูล
- `student-sync` ใช้ verify_jwt=true พร้อม getUser และตรวจ role/admin flag ในฐานข้อมูลอีกชั้น
- รับเฉพาะ operation preview/sync ไม่รับ URL ปลายทางจาก client และไม่ส่ง credentials ไปยัง Google
- ข้อผิดพลาดแสดงค้างใต้ปุ่ม ถ้าถึงขั้นเขียนแล้วขาดการเชื่อมต่อจะแจ้งให้ตรวจประวัติก่อนลองใหม่
